# 내 작업 설명 준비

사용자는 제출 뒤 작업 내용에 대한 질문에 도움 없이 직접 답해야 한다. 사용자가 이해한 상태로 넘어가도록 돕는다.

## 정리할 내용

1. 전체 구조: 주요 파일과 각 파일이 하는 일을 한 줄씩 쓴다
2. 요청 하나가 처리되는 흐름: 입력부터 출력까지 거치는 함수 순서를 쓴다
3. 핵심 판단 세 가지: 무엇을 골랐고 왜 골랐는지, 다른 선택지는 무엇이었는지를 쓴다
4. 약점: 알려진 한계와 그 이유를 쓴다
5. 예상 질문 다섯 개와 답의 요점: 각 답은 두 줄 이내로 쓴다
   - 왜 이 구조를 골랐나
   - 이 부분이 실패하면 어떻게 되나
   - 데이터가 많아지면 무엇이 느려지나
   - 어떻게 검증했나
   - 시간이 더 있으면 무엇을 고치나

## 방식

- 사용자가 모르는 용어는 처음 나올 때 뜻을 붙인다
- 사용자가 직접 만든 판단과 에이전트가 제안한 판단을 구분해서 보여준다
- 문서로 저장하지 말고 대화로만 보여준다. 사용자가 원하면 저장한다
