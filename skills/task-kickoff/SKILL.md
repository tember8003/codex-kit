# 과제 시작

## 절차

1. 작업 공간의 파일 목록을 보고, README와 과제 안내 문서를 끝까지 읽는다
2. 다음을 정리한다
   - 필수 요구사항: 번호를 붙이고 원문 표현을 짧게 인용한다
   - 선택 요구사항이나 가산점 항목
   - 제출해야 하는 파일 이름과 경로
   - 평가 기준이 적혀 있으면 그 내용
   - 모호한 점: 실무자 에이전트에게 물어볼 질문 형태로 쓴다
3. 기존 코드가 있으면 실행 방법과 구조를 파악하고, 실제로 한 번 실행해 본다
4. `PLAN.md`를 만든다. 과제가 계획 문서 이름을 정해 두었으면 그 이름을 쓴다

## PLAN.md 형식

```
# 계획

## 요구사항
1. (요구사항) — 구현 방법 / 검증 방법 / 예상 시간

## 가정
- (근거 없이 정한 것과 그 이유)

## 시간 배분 (총 180분)
- 0~20분: 읽기와 계획
- 20~120분: 필수 요구사항 구현
- 120~150분: 검증과 보완
- 150~170분: 문서 정리
- 170~180분: 제출

## 열린 질문
- (실무자 에이전트에게 물을 것)
```

## 끝낼 때

사용자에게 요구사항 수, 가장 위험한 항목 하나, 먼저 물어볼 질문을 세 줄로 보고하고, 계획에 동의하는지 묻는다.
