# 제출 문서와 제출 점검

## 문서 내용

과제가 문서 이름과 양식을 정해 두었으면 그것을 따르고, 아래 항목이 빠지지 않았는지만 확인한다. 정해 두지 않았으면 README 또는 별도 문서에 다음 절을 쓴다.

1. 무엇을 만들었나: 요구사항 번호별로 구현 여부(완료, 부분, 미구현)
2. 실행 방법: 설치, 실행, 테스트 명령
3. 주요 판단: 고른 방법, 버린 대안, 근거. DECISIONS.md에서 옮긴다
4. 검증 결과: 실제로 돌린 명령과 결과. 숫자가 있으면 숫자로 쓴다
5. 남은 한계: 미구현, 알려진 버그, 시간이 더 있으면 할 일
6. 참고한 외부 자료: 출처와 무엇을 가져왔는지

부풀리지 않는다. 확인하지 못한 것은 확인하지 못했다고 쓴다.

## 제출 직전 점검

- [ ] 과제가 요구한 파일이 정해진 경로와 이름으로 있다
- [ ] 에디터에 저장되지 않은 변경이 없다
- [ ] 전체 테스트를 마지막으로 한 번 돌렸고 결과를 문서에 적었다
- [ ] 마지막 상태를 commit했다
- [ ] 문서에 비밀값, 키, 토큰이 없다
- [ ] 문서 내용과 실제 코드가 어긋나지 않는다

점검 결과를 사용자에게 목록으로 보고한다.
